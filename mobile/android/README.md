# Lastphone for Android

The Android application embeds Lastbook's original Python engine and web UI.
The APK contains CPython through Chaquopy, Android PDF rendering, libkiwix/libzim,
ONNX Runtime and a pinned llama.cpp build with CPU and Vulkan backends. It does
not require Termux, root, an operating-system replacement, or a localhost server.
Library packs and model weights remain separate from the application.

The application ID is `io.github.qqrm.lastphone`. Android 10/API 29 is the minimum;
the build targets API 36. The phone variant supports ARM64. The separate x86_64
variant exists for emulator testing.

## Build on Linux or WSL2

Use Python 3.13, Git, a host C/C++ compiler and FFmpeg. On Debian/Ubuntu the host
packages are `python3.13`, `python3.13-venv`, `git`, `build-essential` and `ffmpeg`.
The bootstrap installs the Android SDK/NDK and JDK in a user-owned directory; it
does not install system packages. On other development hosts, install the same
versions through Android Studio and provide `JAVA_HOME` and `ANDROID_HOME`.

From the repository root:

```bash
python3.13 tools/android/bootstrap_linux.py --accept-sdk-licenses
source "$HOME/.cache/lastphone-toolchain/env.sh"
bash mobile/ipad/scripts/prepare_dependencies.sh
```

`--accept-sdk-licenses` accepts Google's SDK licenses for this development
installation. Omit it to review the SDK manager prompts. A different installation
directory can be supplied with `--directory /path/to/toolchain`; source the
`env.sh` written there. The environment adds the SDK's CMake/Ninja to `PATH`,
which the host Vulkan shader generator also needs.

The checked-in lock file and Gradle files select these versions:

| Component | Version |
| --- | --- |
| Temurin JDK | 21.0.13+9 |
| Gradle wrapper | 8.13, distribution SHA-256 checked |
| Android Gradle plugin | 8.13.2 |
| Kotlin | 2.2.10 |
| Android compile/target SDK | 36 |
| Android build tools | 36.0.0 |
| NDK | 29.0.14206865 |
| CMake | 3.22.1 |
| Chaquopy / Python | 17.2.0 / 3.13 |
| llama.cpp | `dde879bc4f954b809892fd0d660515f42536394a` |

The bootstrap checks the SHA-256 of both its official JDK and Android command-line
tools downloads. Gradle resolves the pinned app dependencies. Native dependencies
are prepared explicitly, including the existing iPad dependency checkout reused
by the Android build. Vulkan and SPIR-V header revisions are pinned in CMake.
Initial development builds require internet access to obtain dependencies.

Build the installable phone APK:

```bash
cd mobile/android
./gradlew --no-daemon assemblePhoneDebug lintPhoneDebug testPhoneDebugUnitTest
```

The output is `app/build/outputs/apk/phone/debug/app-phone-debug.apk`.
Install and launch it on an authorized, USB-debugging-enabled phone:

```bash
adb install -r app/build/outputs/apk/phone/debug/app-phone-debug.apk
adb shell am start -n io.github.qqrm.lastphone/org.lastphone.app.MainActivity
```

Debug APKs use a development signing key generated by the Android build tools.
They can be installed directly. Builds made with a different key cannot replace
an existing installation signed with the previous key.

## Test fixtures and regression tests

Create a host test environment from the repository root:

```bash
python3.13 -m venv "$HOME/.cache/lastphone-host-tests"
source "$HOME/.cache/lastphone-host-tests/bin/activate"
python -m pip install -r tools/android/requirements-host.txt
python tools/android/fetch_test_fixtures.py
python tools/android/make_fixture.py
```

The downloads are the small, revision-pinned TinyStories GGUF and libkiwix ZIM
fixtures; their sizes and SHA-256 values are checked before use. The generated
library contains actual PDF, H.264/AAC video, captions, saved HTML, Unicode FTS5,
map and building geometry. These files go into instrumentation test assets and
are not included in the phone APK. The BGE tokenizer fixture is checked in with
its provenance and hash. Its differential tests use the real host `tokenizers`
implementation. Android uses the tested Python WordPiece adapter.

Run the original engine suite and Android adapter suite:

```bash
python -B -m unittest \
  app.tests.test_readable app.tests.test_bridge app.tests.test_setup \
  app.tests.test_data_folder app.tests.test_what_ships app.tests.test_update \
  app.tests.test_address_search app.tests.test_topic_search app.tests.test_chat_steps \
  app.tests.test_chat_tables app.tests.test_validate_topics app.tests.test_libq
python -B -m unittest discover -s mobile/android/tests -v
```

The setup tests exercise disk-space recommendations. Set `TMPDIR` to a filesystem
with more than 5 GB free if the host's `/tmp` is a small RAM-backed filesystem.
Use a standard Python interpreter: a managed interpreter which inserts additional
certificate authorities changes the upstream test of the app's exact trust store.

Build the emulator app and tests:

```bash
cd mobile/android
./gradlew --no-daemon \
  assembleEmulatorDebug assembleEmulatorDebugAndroidTest \
  lintEmulatorDebug testEmulatorDebugUnitTest
```

With a standard API 36 x86_64 emulator running, use:

```bash
bash ../../tools/android/run_emulator_tests.sh
```

The script requires a 4 KB page-size x86_64 image, runs real instrumentation and
retains device properties, memory information and logcat in
`app/build/reports/emulator`. Use at least 4 GB emulator RAM. Tests exercise actual
JNI GGUF inference, cancellation/reuse, PDF rendering, ZIM reading/search, ONNX
execution, the embedded Python engine, web transport and Android lifecycle.
Vulkan inference is exercised when the emulator exposes a Vulkan backend; the
log records whether the GPU path or the unavailable-device fallback was tested.

For the same instrumentation on an attached ARM64 phone, prepare the fixtures and
run `./gradlew connectedPhoneDebugAndroidTest`. This uses an app-private synthetic
library and changes the test installation's selected data folder. Select the
intended portable data folder again after testing.

## APK inspection and 16 KB pages

Phone and emulator are separate Gradle product flavors. Plain APK ABI splitting
does not remove Chaquopy's native assets, so it is insufficient for this project.
The phone APK includes ARM64 only. Every native ELF, including Python extensions
inside `.imy` archives and versioned libraries such as `.so.3`, must have load
segment alignment of at least 16 KB. The validator also checks the APK signature,
ZIP alignment, ELF architecture and absence of GGUF/ZIM data in the app package.

From the repository root:

```bash
python tools/android/verify_apk.py \
  mobile/android/app/build/outputs/apk/phone/debug/app-phone-debug.apk \
  --abis arm64-v8a --report mobile/android/app/build/reports/apk-arm64-verification.json
python tools/android/verify_apk.py \
  mobile/android/app/build/outputs/apk/emulator/debug/app-emulator-debug.apk \
  --abis x86_64 --minimum-load-alignment 4096 \
  --report mobile/android/app/build/reports/apk-emulator-verification.json
```

The emulator variant has two upstream x86_64 NumPy dependencies with 4 KB ELF
alignment (`libopenblas.so` and `libgfortran.so.3`). It is explicitly a 4 KB test
target and is not the downloadable phone build. The ARM64 versions pass the
16 KB alignment check. Binary alignment is a packaging check; execution on a
physical 16 KB ARM64 device remains a separate acceptance test.

## CI and signing

`.github/workflows/android.yml` runs the original engine and adapter tests,
builds both flavors, checks lint/unit tests and both APKs, then runs Android
instrumentation on a hardware-accelerated emulator. Failure of any required
step prevents publication of the APK artifact. Verification reports are retained
on failure. The downloadable artifact is `lastphone-arm64-debug-tested`, containing
the phone APK and its SHA-256 file. This validates Android integration on x86_64
and the ARM64 binary build; it is not a claim of physical Nubia GPU testing.

For a signed release, set `LASTPHONE_KEYSTORE`, `LASTPHONE_STORE_PASSWORD`,
`LASTPHONE_KEY_ALIAS` and `LASTPHONE_KEY_PASSWORD` in the build environment, then
run `./gradlew assemblePhoneRelease`. Keep the keystore and passwords outside the
repository. Without release credentials, the release variant remains unsigned;
the debug key is never substituted for a production key.

## Remaining device acceptance

The original regression suite passed 335 tests with four platform/fixture skips
under standard Python 3.13 on 2026-11-18. Build, package and instrumentation status
should be read from the matching GitHub Actions run and its reports.

The target phone's device tree does not establish its RAM capacity, installed
firmware or GPU-driver behavior. Physical acceptance must record those details,
page size, model hash, selected backend and context length. Measure memory,
cold/warm loading, sustained generation, thermal behavior, background transitions
and cancellation with the intended model and real data packs. See
[`docs/LASTPHONE_PARITY.md`](../../docs/LASTPHONE_PARITY.md) for the full acceptance
matrix. No NPU acceleration or token-rate figure is promised by the port.

## Source and licenses

The app packages dependency notices and license texts with its engine assets.
libkiwix/libzim introduce GPL obligations into Android distribution; preserve the
upstream MIT notices and the dependency licenses. Distribute the matching source
revision and the build scripts alongside any public APK, including the pinned
native dependency revisions and any build patches. A binary-only copy of the
application is not the project's source-distribution strategy.
